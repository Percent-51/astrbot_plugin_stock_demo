# 群聊股市插件 · 移植指南

> 一句话：股价不靠掷骰子，靠群友在 Bot 里的**真实行为**当基本面。
> 零 LLM、零 token、零外部依赖。装进 AstrBot 就能跑，接上你自己的玩法数据就活。

---

## 0. 包里有什么

```
astrbot_plugin_stock_demo/
  main.py              全部逻辑（单文件，约 2100 行）
  metadata.yaml        AstrBot 插件元信息
  _conf_schema.json    插件配置（只有 group_id 一项）
  docs/移植指南.md     本文件
  tests/冒烟回归.py    自测脚本（89 条断言，改完代码可以跑一下）
```

**保留了**：噪声行情、5 分钟 tick、随机事件池、黑天鹅、买卖/持仓/手续费、
分红、退市重组、行情卡、联动卡、收益榜、话题热度、剧情行情、资金面冲击。

**没包含**（是我自己群的后门，跟玩法无关，全删干净了）：
AI 做市（LLM 后台调参）、私聊庄家密语（挠痒痒/黑天鹅/剧情/定盘）、
股市大赦、私聊暗盘交易。

## 1. 三分钟装上（先跑起来）

1. 放进 AstrBot 的 `data/plugins/` 下面（跟其他插件同级）：

   ```bash
   cd <AstrBot 根目录>/data/plugins
   git clone https://github.com/Percent-51/astrbot_plugin_stock_demo
   ```

   也可以下载 zip 解压后把整个目录丢进去。最终结构应该是：

   ```
   <AstrBot 根目录>/data/plugins/astrbot_plugin_stock_demo/main.py
   ```

   ⚠️ 别多套一层目录（`plugins/xxx/astrbot_plugin_stock_demo/`），AstrBot 扫不到。

2. 打开 `main.py`，改顶部这两行（见 §2.1）：

   ```python
   PLUGIN_NAME = "astrbot_plugin_stock_demo"   # 必须和目录名一致
   GROUP_ID = "123456789"                      # ★ 改成你的群号
   ```

3. 重启 AstrBot。启动日志里应该出现：

   ```
   [StockDemo] 股市插件已加载：群 你的群号｜5min tick｜6 只股｜噪声+事件+黑天鹅+联动+资金面
   ```

   ⚠️ 如果看到 `[StockDemo] 还没填群号！` 这行警告，说明 `GROUP_ID` 还是占位的
   `123456789` —— 此时插件**不会响应任何消息**，改完重启即可。

4. 群里发一句 `小堡股市：规则`，有回就通了。再发 `小堡股市：行情` 看卡。

**此时的状态**：行情会动（噪声 + 事件 + 黑天鹅），但**联动全是 0**
（因为还没接数据源）——这是正常的，见 §2.2。

## 2. 只改三个地方

整个插件只有三块需要你动，其余一行不用碰。

### 2.1 顶部配置（10 秒）

```python
PLUGIN_NAME = "astrbot_plugin_stock_demo"   # 插件目录名，数据存到 data/plugin_data/<这个名字>/
GROUP_ID = "123456789"                      # ★ 你的群号（也可在插件配置里填 group_id 覆盖）
CMD_PREFIXES = ("小堡股市：", "小堡股市:", "小堡股市 ")
```

`CMD_PREFIXES` 是指令前缀，群友发 `小堡股市：行情` 触发。
想换成 `股市：` 就改成 `("股市：", "股市:", "股市 ")`（三种写法都要给，
因为群友打全角冒号、半角冒号、空格的习惯都不一样）。

### 2.2 数据源适配器（主要工作量）

在 `main.py` 里搜 `SOURCES = {`，这是唯一需要你「动脑对接」的地方。

**接口约定**——每个指标实现一个函数：

```python
def my_source(day: str, gid: str) -> float:
    """day = "2026-10-20"（今天），gid = 群号
    返回：该指标「今日累计值」（次数 / 金额 / 局数，单位随指标而定）"""
```

**安全约定**：返回 `0` 表示今天没数据；**抛异常会被捕获并按 0 处理**，
联动只会显得冷清，绝不会把插件搞崩。所以接错了也不会炸，放心试。

**已经给了两个工具**：

```python
# ① 跨插件读 JSON（最常用）
def _read_json(plugin_dir: str, filename: str) -> dict:
    """从别的插件的数据目录读一个 JSON；读不到/坏档都返回空 dict。"""

# ② 一个完整可跑的示例（照抄改路径就行）
def _src_checkin(day, gid):
    data = _read_json("your_plugin_dir", "state.json")
    users = ((data.get("groups") or {}).get(gid) or {}).get("users") or {}
    n = 0
    for u in users.values():
        d = (u.get("daily") or {}).get(day)
        if isinstance(d, dict) and d.get("checkin"):
            n += 1
    return float(n)
```

**没接的指标保持 `_zero` 就行**，插件不会报错，只是那只股少了这块驱动。

> 建议上手顺序：先接 **1~2 个你最在意的指标**（比如签到、游戏局数），
> 发 `小堡股市：联动` 看卡上那个数字会不会跟着变。通了再补其他。

### 2.3 货币接口（两个函数）

在 `main.py` 里搜 `★★★ 货币接口`：

```python
def get_balance(self, uid: str) -> int:
    """查余额"""

def add_coins(self, uid: str, name: str, amount: int) -> None:
    """加/扣币（amount 可为负，扣到 0 为止）"""
```

**默认实现是插件内置的本地钱包**（存在 `stock.json` 的 `wallet` 表里），
好处是拷过去就能跑。如果你已经有堡贝/金币系统，把这两个函数体换掉即可：

```python
def get_balance(self, uid: str) -> int:
    menu = self._你的账本桥()
    return int(menu.get_user(uid).get("coins", 0) or 0)

def add_coins(self, uid: str, name: str, amount: int) -> None:
    menu = self._你的账本桥()
    u = menu.get_user(uid)
    u["coins"] = max(0, int(u.get("coins", 0) or 0) + amount)
```

**注意**：`add_coins` 会被这些地方调用——买入扣款、卖出到账、退市退款、
分红派发、亏损日扣款。只要这两个函数对，钱就对了。

## 3. 联动源怎么设计

每只股吃一组「联动源」，定义在 `STOCKS` 里：

```python
"XBK": {"name": "蟹堡王", "vol": 1.0, "limit": 0.22, "sources": [
    ("checkin", 0.25), ("pet", 0.20), ("fed_meals", 0.20), ("play", 0.15),
    ("bite", 0.10), ("run_km", 0.10)]},
```

- `vol`：股性，噪声和基本面弹性都乘这个数。`<1.2 稳健`、`<1.5 活跃`、`≥1.5 疯狂`。
- `limit`：这只股的涨跌停幅度（相对本周期开盘价）。
- `sources`：`(指标键, 权重)`。**正权重越多越涨；负权重 = 反向源**（数值越大越压股价）。

### 三条经验（都是我踩过的）

**① 权重和不必强凑 1.0，但正权重别超太多。**
含反向源的股（如 BBB：`0.30+0.15-0.15+0.25+0.15=0.70`）本来就凑不满。
正权重和越大，单日漂移越猛——满热度理论上一整天能推三四十个点，
再大就天天涨停了（涨跌停、均值回归和噪声会压掉一部分，但方向是对的）。

**② 低频指标必须登记到 `LOWFREQ_KEYS`。**
日均只有 0~5 次的指标（游戏开局局数、表白次数、生娃数），
如果不登记，热度比值的平滑地板会用默认的 `3.0`，把 ratio 死死压在 1.0 附近
——那只股就变成死板，怎么玩都不动。登记后地板取 `1.0`，动态范围才出来。

**③ 金额和次数不能混。**
金额类（存款、贷款、红包流水、彩票流水）走 `log1p` 差 ×100 归一，
`MONEY_KEYS` 里的键会被当金额处理；次数类直接算比值。
把「记账笔数」填成「存款金额」这种错，会让那只股一天涨十倍。

## 4. 参数速查（想调手感看这里）

| 参数 | 现值 | 作用 |
|---|---|---|
| `TICK_SEC` | 300 | 一个 tick 5 分钟，**对齐整 5 分钟刻度** |
| `INIT_PRICE` | 10.0 | 初始股价 / 退市重组价 |
| `NOISE_SIGMA` | 0.15 | 单 tick 噪声 σ（×股性 vol，再 ×0.141） |
| `SENSE` | 0.16 | 基本面灵敏度：权重和 × 0.55 × 本值 ÷ 72 每 tick，越大漂移越猛 |
| `TICK_CAP` | 0.12 | 单 tick 封顶 ±12% |
| `EVENT_CHANCE` | 0.006 | 每股每 tick 自发事件概率（≈每小时一场） |
| `EVENT_MIN_PCT` / `MAX_PCT` | 0.08 / 0.28 | 事件幅度 ±8%~28% |
| `BLACK_SWAN_CHANCE` | 0.0002 | 黑天鹅概率（全群 3~5 天一次） |
| `BLACK_SWAN_MIN` / `MAX` | 0.40 / 0.60 | 黑天鹅幅度，**突破涨跌停** |
| `REGIME_CHANCE` | 0.12 | 每周期开「剧情行情」的概率（2 小时单边，不播报） |
| `FEE` | 0.003 | 手续费 0.3% 双向，**全部进金库** |
| `FLOW_CAP` | 0.06 | 资金面单周期位移封顶 ±6% |
| `FLOOR_LINE` | 5.0 | 面值线：低于它开始计退市倒计时 |
| `FLOOR_STREAK_MAX` | 24 | 连续 24 个 tick（2 小时）→ 退市清算 |
| `DELIST_REFUND` | 0.5 | 清算退款 = 现价 5 折（自己卖是全价） |
| `DELIST_PAUSE_SEC` | 7200 | 退市后停牌 2 小时再重组 |
| `LK_BCAST_SEC` | 1800 | 联动热度播报节流：30 分钟一次 |
| `LK_QUIET_HOURS` | (3, 9) | 3:00~9:00 不播报 |
| `LB_HOUR` | 20 | 每晚 20:00 播今日收益榜 |

**手续费 → 金库 → 分红** 是个闭环：群友交易交的手续费进 `div_pool`，
每晚 22:05 按 XBK 持股比例分给股东；`div_pool` 为负时反向共担（扣到余额清零为止）。
这是让「持股」有意义的唯一机制，别删。

## 6. 常见坑

**① 只在本群响应。**
`on_message` 里有一句 `if gid != self.group_id: return` —— 私聊、别群一律静默，
防止别处误触发把行情搞乱。想支持多群，把它改成集合判断：

```python
if gid not in self.group_ids: return
```

**② 播报要「先说过话」。**
群播报（事件/热度/收益榜）发到 `self.umos[group_id]`，这个值在**该群第一次
发指令时**才被填上（之后随存档持久化）。所以刚装好、还没人在群里发过指令时，
不会有播报——这不是 bug。

**③ 数据源返回 0 不是错。**
接错了、路径写错了、JSON 结构不对，全都是「返回 0 + 静默」。
所以「联动卡上数字恒为 0」时，去函数里临时加一行
`logger.info("checkin=%s", n)` 确认到底进没进。

**④ 跨日残留要校验日期。**
如果你读的是「每人每天一个计数器」（比如 `daily[uid] = {day, count}`），
**必须校验 `day` 字段**，否则昨天没清掉的量会被算进今天。
`_src_checkin` 里那句 `if d.get("day") == day` 就是干这个的。

**⑤ 别把两种行为混成一个源。**
比如「摸机器人」和「群友互相摸」——前者是个体行为、后者是社交行为，
混在一个指标里，那只股的涨跌就会跟群友的直觉对不上。

**⑥ 重启不补价。**
tick 对齐整 5 分钟刻度，重启后从下一个刻度开始，不会把停机期间的行情补上。
这是刻意的（补价会造出一根假的巨幅 K 线）。

**⑦ 状态文件名是 `stock.json`**，在
`data/plugin_data/astrbot_plugin_stock_demo/` 下。想重置就直接删它。

## 7. 想改得更像自己的群

- **股名和题材**：`STOCKS` 里改 `name`；事件池 `EVENTS`（每股 12 条、正负各 6）
  和黑天鹅池 `BLACK_SWAN_EVENTS`（每股 4 条、正负各 2）里换成你们群的黑话梗。
  **保持正负 1:1**，否则长期会单边漂移。
- **加第 7 只股**：在 `STOCKS` 里加一项（`vol` / `limit` / `sources`），
  在 `EVENTS` / `BLACK_SWAN_EVENTS` 里补池子，再到 `_LK_COLORS` / `_LK_EMOJI`
  里补配色和 emoji（联动卡、行情卡会自动扩容）。
- **股性**：`vol` 越大越疯。稳健 1.0 / 活跃 1.3~1.5 / 疯狂 1.7~1.8。
- **想加「AI 后台调参」**：这版删掉了，但结构还在——加一个独立协程读
  `_state` 里的行情、算出 `bias/strength` 写进 state，在 `_tick_locked` 的
  `move` 上叠加即可。**注意**：加常数不改变方差，所以推力太小是白费力气；
  而且要加逆势保护（已高估还看涨要打折），否则会把跑偏的股推去退市。
